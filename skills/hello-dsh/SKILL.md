# Hello DSH

先原样输出这一行：

**HELLO DSH — 这句话来自 ~/.dsh/skills/hello-dsh/SKILL.md**

然后用一句话说明：这句话不在你的训练数据里，是刚才通过 `skill` 工具从本地磁盘的一个 Markdown 文件读到的。

最后问用户想从哪里开始。

## 按层讲，一次一层

**用户问到哪层讲哪层，讲完停下来问要不要继续。不要一口气倒完。**

### 第一层：技能就是一个文件

```
~/.dsh/skills/<名字>/SKILL.md
```

没有编译，没有注册表，没有 npm 包。DSH 扫描约定目录，解析每个 `SKILL.md` 的 frontmatter，组成一份目录给模型看。

模型最初**只看到目录**（`name` 和 `description`），正文要等它决定加载后才读进来。所以 `description` 是触发条件，比正文更重要。

### 第二层：生命周期

让用户自己跑一遍，**全程不用重启**：

```sh
rm -rf ~/.dsh/skills/hello-dsh        # 删掉 → 问模型，答「没有」
# 把文件写回去                          # 放回 → 再问，答「有」并能加载
```

文件出现技能就在，文件消失技能就不在，中间没有任何重启动作。

### 第三层：技能还是插件

| 你要做的事 | 用 |
|---|---|
| 改变模型的判断标准、输出格式、工作流程 | **技能**（Markdown，5 分钟） |
| 注册新工具、接外部服务、挂生命周期钩子 | **插件**（TypeScript） |

判断依据：**用自然语言能说清楚的，就是技能。**

写插件有三个新手必踩的坑，都在完整教程里：必须 `defineTool()` 包裹并声明 `output`、`required` 只能填 `true`、模块里不能有 `export default`。

### 第四层：背后的原理

DSH 建立在 Cordis 之上，有一篇论文《A Programming Paradigm for Spatiotemporal Composability》。上面第二层那个演示，正是论文形式化内容的最小可观察实例：

- **时间可组合性**（§3.1）：组件移除时其影响被完整撤销。每个作用携带逆操作，卸载时按 LIFO 恢复。对比：VSCode 安装量前 100 的扩展里 **87 个**卸载必须重启宿主（§1.2.1）。
- **空间可组合性**（§3.2）：组件声明依赖，运行时在依赖出现/消失时重新判断它能否运行。依赖不满足时**静默不激活，不报错**——这是排查技能问题的重要线索。
- **两状态生命周期**（§4.1 图 1）：`Inactive ⇄ Active`，由「当前生效的视图」和「目标视图」的比较驱动。

**不读论文也能用。** 知道之后两件事变得可预期：为什么改完不用重启，以及为什么技能"明明在那儿却不生效"。
