# Hello DSH

先原样输出这一行：

**HELLO DSH — 这句话来自 ~/.dsh/skills/hello-dsh/SKILL.md**

然后用一句话说明：这句话不在你的训练数据里，是刚才通过 `skill` 工具从本地磁盘的一个 Markdown 文件读到的。

最后问用户想从哪里开始。

## 按层讲，一次一层

**用户问到哪层讲哪层，讲完停下来问要不要继续。不要一口气倒完。**

### 第一层：DSH 里一切皆插件

这是 DSH 的核心设计，官方 README 的第一句话就是 *"Everything is a Plugin"*。

不只是"支持插件扩展"，而是**产品自身就是插件拼出来的**：模型适配器是插件，工具注册表是插件，会话日志是插件，连 agent 主循环本身都是插件。

刚才那句暗号就是证据。让它成为可能的是四个插件协作：

| 插件 | 干什么 |
|---|---|
| `dsh-skill` | 定义「技能」这个能力 |
| `dsh-skill-filesystem` | 扫描目录、读取 Markdown 文件 |
| `dsh-tool-skill` | 把技能目录给模型看，提供加载工具 |
| `dsh-client-ui-skill` | Web UI 里的技能界面 |

**你要给 DSH 加东西，也是加插件。** 两条路：

| 路 | 写什么 | 成本 | 适合 |
|---|---|---|---|
| **技能插件** | 一个 Markdown 文件 | 5 分钟 | 改变判断标准、输出格式、工作流程 |
| **代码插件** | TypeScript 模块 | 半小时起 | 注册新工具、接外部服务、挂生命周期钩子 |

**判断依据：用自然语言能说清楚的，走 Markdown 那条路。**

（严格说，技能是被 `skill-filesystem` 插件读取的数据文件，本身不是 Cordis 意义上的插件实体。这个区别在写代码插件时才需要在意，用的时候不影响。）

### 第二层：生命周期

让用户自己跑一遍，**全程不用重启**：

```sh
rm -rf ~/.dsh/skills/hello-dsh        # 删掉 → 问模型，答「没有」
# 把文件写回去                          # 放回 → 再问，答「有」并能加载
```

文件出现就在，文件消失就不在，中间没有任何重启动作。

代码插件也一样：改完源码不用重启进程，HMR 会替换掉旧的 fiber。

### 第三层：写一个代码插件

三个新手必踩的坑，都是实测出来的：

1. **必须 `defineTool()` 包裹，且声明 `output { schema, render }`**
   否则报 `must declare output {...}`
2. **`required` 只能填 `true`**，可选参数直接省略这个字段
   否则报 `UNSUPPORTED_SCHEMA`
3. **模块里不能有 `export default`**
   否则 Loader 会丢掉 `inject`，报 `cannot get property "xxx" without inject`。这个坑官方自己踩过并写了事故复盘，当时有 178 个绿色测试和 100% 覆盖率都没抓到

另外：`parameters` 是**扁平字段映射**，而 `output.schema` 是**标准 JSON Schema**，两者形态不同。

完整可运行的例子和每一步的真实报错，见教程。

### 第四层：背后的原理

DSH 建立在 **Cordis** 之上，有一篇论文《A Programming Paradigm for Spatiotemporal Composability》。第二层那个演示，正是论文形式化内容的最小可观察实例：

- **时间可组合性**（§3.1）：组件移除时其影响被完整撤销。每个作用携带逆操作，卸载时按 LIFO 恢复。对比：VSCode 安装量前 100 的扩展里 **87 个**卸载必须重启宿主（§1.2.1）。
- **空间可组合性**（§3.2）：组件声明依赖，运行时在依赖出现/消失时重新判断它能否运行。依赖不满足时**静默不激活，不报错**——这是排查「插件装了没反应」的第一个方向。
- **两状态生命周期**（§4.1 图 1）：`Inactive ⇄ Active`，由「当前生效的视图」和「目标视图」的比较驱动。

**不读论文也能用。** 知道之后两件事变得可预期：为什么改完不用重启，以及为什么插件"明明在那儿却不生效"。

## 一个必须提醒用户的坑

**Web UI 默认关闭了技能功能**（`headless` 是开的）。用 `dsh web` 时技能不会生效，需要显式打开：

```sh
npx @deepseek-ai/dsh web --patch ./enable-skills-in-web.yml
```

这个文件在 hello-dsh 仓库根目录。实测于 `0.1.0-rc.6`。

## 讲解时不要做的事

- 不要一次把四层全倒出来
- 不要在用户只想跑通时讲论文
- 不要搬论文的形式化符号，讲行为就够
- 不要说「技能就是提示词」，它有生命周期、优先级、依赖，提示词没有
